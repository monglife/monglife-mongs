### ★ 신규 결함 — 종료된 매치를 다시 강제 종료하면 상태가 덮인다

`Match.adminEnd()` 가 `end()` 를 무조건 호출한다. 종료 상태 가드가 없다.

**재현** — `CANCELED` 인 매치 `#7` 에 강제 종료를 한 번 더 호출:

```
POST /admin/battle/matches/7/terminate  →  200
stateCode: CANCELED → END,  round 0,  payPoint 650 → 650 (환불 반복 없음)
```

실제로 이번 테스트에서 자연 발생했다. 매치 `#6` 은 스위퍼가 `CANCELED` 로 마감한 직후 관리자 강제 종료가 들어가 `END` 로 덮였다(terminate 호출은 네트워크 로그상 1회).

**영향** — 돈은 안전하다. `cancelEnteringMatchUseCase` 가 빈 값을 돌려주므로 환불이 반복되지 않는다. 문제는 기록이다.

- `CANCELED` 감사 기록이 사라지고 `END` + `round=0` 이 된다. **이번 배포가 `CANCELED` 를 새로 만든 이유가 바로 그 모호한 서명을 없애려는 것이었다.**
- `MATCH_END` 가 한 번 더 발행된다.

**현실성** — 낮지 않다. 관리자 목록은 30초 주기로 갱신되고 기한도 30초라, 스위퍼가 방금 취소한 매치의 "강제 종료" 버튼이 화면에 남아 있는 구간이 늘 존재한다.

`forceEndMatchPort` 에서 `isTerminal()` 이면 건너뛰거나, `adminEnd()` 에 가드를 두면 닫힌다. (코드 프리징 중이라 손대지 않았다.)
